    coding agent

    英文版：README.md

    coder 是一个交互式 coding agent：它读代码、写代码、跑命令，然后告诉你它改了什么。 它能跑在终端里，也能跑在浏览器里，还是一个能当库用的东西。

    pip install coder-agent
cd my-project

coder                        # 终端界面
coder web                    # 同一个 agent，跑在浏览器里
coder eval path/to/suite     # 拿一个任务集跑这个 agent

    这个包已经发到 PyPI 上。想跟着仓库走： pip install "coder-agent @ git+https://github.com/sds819/coder-agent"。

    它能做什么

    工具。 十四个内置工具：read、write、edit、multi_edit 和 apply_patch 改文件； glob、grep 和 ls 找代码；bash、bash_output 和 bash_kill 跑命令（也能放后台跑）； todo_write 记任务清单；task 起一个子 agent；skill 加载技能。

    权限。 五种模式：default（凡是会改动东西的都问）、acceptEdits（写文件直接过，其余 还是问）、plan 和 readonly（什么都不改）以及 bypass（什么都不问）。规则写在 ~/.coderagent/rules.yaml（你的）和 .coderagent/rules.yaml（项目的）里；deny 永远压过 allow。

    会话。 每个会话都有一份事件日志，所以它能被续接（coder --resume）、分叉（/fork）、 回退（/rewind）和导出（coder export）；会话的轨迹还能发给 OpenTelemetry 采集器。 浏览器里开的会话能在终端里接着跑，反过来也一样。

    上下文。 对话到预算的 80% 会被压缩；摘要留着目标、发现、决定、动过的文件和还没解决的问题。 一轮结束前按顺序过三道闸门：Stop hook、项目的 verify.commands、输出 schema。

    记忆。 项目把记忆写在 .coderagent/memory/*.md，你自己的偏好写在 ~/.coderagent/CLAUDE.md， /init 给仓库写一份 AGENTS.md。

    子 agent 和路由。 task 起一个子 agent（code-explorer、verifier、refactorer， 还有你自己写的）。不同的活可以用不同的模型：main、cheap、strong、summarize、 reflect 和 review。

    扩展。 九个事件上的 hook（PreToolUse、PostToolUse、UserPromptSubmit、Stop、 SessionStart、SessionEnd、SubagentStop、PreCompact、PostCompact）、MCP server、插件、 技能和自定义 slash 命令。

    沙箱。 命令可以跑在 local、docker、singularity、bubblewrap、contree 或者 SWE-ReX（swerex_docker、swerex_modal）里。

    35 个 slash 命令（/model、/mode、/plan、/review、/diff、/cost、 /context、/compact、/resume、/fork、/agents、/permissions、/hooks、/sandbox 等）—— 浏览器里是同一套。

    网页版。 coder web 提供聊天页、设置页（模型和权限都是表单）、文件树和这一轮改动的 diff。 每个动作都是普通 HTTP 调用，所以脚本也能驱动它；API 文档在 /api/docs。

    评测。 coder eval <suite> 拿一个任务集跑 agent，并报告每个任务的结果； coder eval-compare 比对两份报告，指出哪些任务退化了。

    警告

    网页版没有认证：能访问端口的人就能驱动 agent 在当前目录里跑命令，所以默认只听 127.0.0.1。

    模型

    模型走 litellm，所以 litellm 支持的模型都能用，只要带上 厂商前缀（anthropic/…、deepseek/…）。厂商的 key 从环境变量读（ANTHROPIC_API_KEY、 OPENAI_API_KEY 等），或者从 ~/.coderagent/.env 读。

    coder -m deepseek/deepseek-flash --task "修好那个失败的测试"

    模型可以在终端、终端界面和浏览器里配置，三处写的是同一个文件：~/.coderagent/config.yaml。

    coder model                                                   # 看看当前生效的设置
coder model --name deepseek/deepseek-flash --max-retries 3    # 把设置写下来
coder model --test                                            # 试一下这个模型

    试一下和写下来是两件事：--test 什么都不写，写下来也不等试的结果——暂时还不好用的配置也值得 先写下来，等下再修。终端界面里也是这三步（/model name=… base=… key=… retries=…、 /model --test、/model --save），浏览器的设置页上则是保存旁边的一个测试按钮。

    图片。 把图片发给一个谁也不了解它能不能看的模型时，agent 会问它一次——发一张纯色的图， 问它是什么颜色——然后把答案写进你自己的配置文件。下一次配置里已经有答案了，就不再问。 看不到图片的模型会被直接拒绝这一轮，而不是编一个答案出来。

    有问题

    • 哪儿坏了：提一个 bug——模板里会问 报错信息和复现步骤。最近一次会话的日志在 ~/.coderagent/sessions（coder export 能导出来）。
    • 报错看不懂：功能里每一节都有「出错了怎么办」。
    • 想问个问题：提一个问题，或者到 Discord 上说。

    来历

    这个 agent 建立在 mini-swe-agent 的想法之上： 消息的线性历史、只用 bash 一个工具跑命令、litellm 的模型层，以及随它而来的那些沙箱环境 （Docker、Singularity、bubblewrap、contree、SWE-ReX）。其余的——agent 的循环、工具系统和权限层、 会话和事件日志、上下文引擎和它的压缩、记忆、子 agent 和模型路由、扩展（hook、MCP、插件、 技能）、终端界面、网页界面和评测工具——都是新的。
